1. Abstract & Executive Summary

As decentralized ecosystems expand, trustless capital formation remains the foundational catalyst for developer adoption and liquidity growth. BotLaunch is the native decentralized token launchpad built specifically for the Botchain ecosystem.

Engineered to resolve the rampant vulnerabilities of unregulated presales, BotLaunch operates as a strictly non-custodial escrow platform. Project creators deploy standard ERC-20 tokens via an on-chain wizard and launch sales with customizable parameters (soft caps, hard caps, durations, and contribution limits). Investors commit native BOT with mathematical guarantees: 1-click token claims upon sale success, or an automated 100% BOT refund directly from the smart contract if a project fails to achieve its soft cap.

Core Axiom: Zero custodian discretion. Zero simulated transactions. All states, funds, and token distributions are governed exclusively by immutable smart contract code.

2. The Problem Statement

Early-stage fundraising in nascent blockchain ecosystems faces systemic friction that harms both builders and investors:

⚠️ Custodial Rugpull Risks

In standard informal presales, investors send funds directly to developer EOAs (Externally Owned Accounts). If the project underperforms or creators abandon ship, contributors face 100% capital loss with zero recourse.

⚠️ Friction in Token Deployment

Emerging developers often lack audited contract templates, resulting in non-standard ERC-20 tokens with vulnerabilities, unverified code, or broken transfer logic.

⚠️ No Automated Refund Rails

When funding targets fail to reach viability thresholds, developers rarely execute manual refunds, locking investor liquidity indefinitely.

⚠️ Whale Manipulation

Without on-chain per-wallet contribution minimums and maximums, automated bots and whales siphon token supply, distorting healthy decentralized distribution.

4. Smart Contract Architecture & Lifecycle

The BotLaunch protocol architecture consists of two tightly coupled smart contract modules:

contracts/ ├── BotToken.sol # Standard OpenZeppelin ERC-20 project token implementation └── BotLaunchpad.sol # Non-custodial escrow, accounting & distribution engine

The On-Chain Sale Lifecycle

Every sale transitions through deterministic, verifiable states:

  1. Creation & Solvency Lock: Creator deploys token, approves launchpad, and defines sale configuration. The launchpad transfers and locks the required token allocation into escrow.
  2. Public Contribution Window: Investors contribute native BOT within the authorized timestamp range (startTime to endTime).
  3. Finalization Trigger: Once hardCap is attained or endTime lapses, the creator or protocol finalizes the sale.
  4. Settlement Branch:
    • If Soft Cap Reached (Success): Contributors call claimTokens(). Creator executes withdrawFunds() to receive raised BOT, plus withdrawUnsoldTokens() if hard cap wasn't fully reached.
    • If Soft Cap Missed (Failed): Contributors call claimRefund() to withdraw 100% of their deposited BOT. Creator reclaims all escrowed tokens via withdrawUnsoldTokens().

5. Pricing & Mathematical Engine

The pricing engine is implemented in pure integer arithmetic in Solidity ^0.8.24, preventing rounding inaccuracies, precision loss, and overflow vulnerabilities.

Allocation Calculation Formula

The token allocation for any contributor committing msg.value native BOT is defined as:

tokenAllocation = (msg.value * 10^tokenDecimals) / tokenPrice

Where tokenPrice denotes the cost in native BOT wei required to purchase 1.0 whole project token (1018 base units).

Strict Escrow Solvency Invariant

To guarantee that the smart contract can never be insolvent or unable to fulfill user claims, sale creation strictly enforces the solvency inequality:

escrowTokenAmount >= (hardCap * 10^tokenDecimals) / tokenPrice

Any attempt to initialize a sale without locking sufficient tokens immediately reverts.

6. Security Specifications & Verification

The protocol enforces rigorous industry security standards:

🛡️ Reentrancy Protection

Every state-modifying external function utilizes OpenZeppelin's battle-tested ReentrancyGuard.

🔒 Checks-Effects-Interactions

Internal accounting flags (claimed, refunded, fundsWithdrawn) are updated prior to any token or native BOT transfer.

⚡ SafeERC20 Transfers

Wrapped transfer primitives prevent silent reverts or non-compliant ERC-20 return values from freezing escrow state.

🧪 25-Scenario Hardhat Test Suite

Comprehensive unit and integration test suite verifying lifecycle transitions, edge cases, timing boundaries, and stress bounds.
